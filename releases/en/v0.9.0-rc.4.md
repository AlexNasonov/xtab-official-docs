The fourth candidate of version 0.9 for the pilot: improvements after the remarks of the pilot and fixes.

**Improvements**
- The interface builder: a «Layout / Preview» switch — the page with the real data of the base as its users will see it; the draft saves itself; when the draft was changed in another tab or by another creator, the builder offers to load the saved one or to save yours over it.
- The width of the settings panel of the builder changes by dragging its border or from the keyboard and is remembered; filter conditions fit the panel without scrolling sideways.
- A grid, a list and a kanban on a page of an interface stretch to the bottom of the window.
- Automations: «Try on a record» — a trial run on a chosen record before turning the automation on: HTTP requests are really sent, changes of the record are shown as «was → becomes» without saving, emails are not sent.
- Values of the answer of an «HTTP request» step are available to the next steps through the `STEP` function: fill the fields of a record with data of an external service, for example; the step has an «On error: stop the run / go on» setting.
- The automation editor warns when an API key is typed into a header as plain text and hints how to put values of fields into the address and the body of a request.
- Actions on a base and a workspace — access, copying, renaming, deleting — are gathered in the «Manage base» and «Manage workspace» menus; only the allowed ones are shown.
- An «All tables» menu with a search over the tables of a base; tabs of unneeded tables can be hidden for oneself and brought back.
- Separators in the row of the tabs of a base, a «+ New grid» item, the xtab mark in the browser tab.
- A button to show the value in every field of a password or a key.

**Fixes**
- A grid with grouping, sorting or a filter: one's own edited, pasted or new record jumped away or disappeared, the selection stayed on other records, the numbers in group headers lagged behind; now the record stays in place while you are on it.
- A count of records with a filter or a search on a large table failed instead of giving an approximate number.
- The interface builder: a record card over another table of the base was not saved; an interface was not saved when an element kept a deleted field (it is now marked «Field deleted»); new fields of a table were not seen until the page was reloaded.
- An interface element where records may only be created added empty records that could not be filled in; now «+» opens a window of a new record.
- The new record button covered the bottom rows of the grid.
- The second factor code step did not fit the login card.
- The command creating a second organization gave a broken invitation link; now it refuses with a hint.
