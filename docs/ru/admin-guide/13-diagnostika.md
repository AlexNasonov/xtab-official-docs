## `xtab doctor`

Первое, что стоит запустить при любой проблеме:

```bash
docker compose exec xtab-worker xtab doctor            # полная проверка узла: конфигурация, база, роли, хранилище, почта, ключи, копии
docker compose run --rm migrate doctor                 # база, схема, роли и ключи — без запуска узла
docker compose run --rm migrate doctor --storage-probe # хранилище с составной загрузкой
docker compose exec xtab-worker xtab doctor --mail-probe # почтовый сервер: подключение, вход, отправитель
```

Она проверяет:

- конфигурацию;
- версию PostgreSQL и расширения;
- роли и права базы, бюджет соединений;
- хранилище и почту;
- часы и лицензию;
- давность резервной копии и проверки восстановления.

Каждая строка — «в порядке», предупреждение или ошибка с подсказкой. Вывод в JSON — `--format json`.

Проверка почты `--mail-probe` подключается к почтовому серверу с заданной защитой и проверкой сертификата, входит и предлагает адрес отправителя, но письма не отправляет. Её запускают на узле фоновых задач: только у него есть выход к почтовому серверу. Ответ называет причину: нет соединения, сертификат, неверный логин или пароль, отправитель не принят (например, адрес не своего ящика и не его алиас). Установщик выполняет ту же проверку до записи настроек, если в ответах задан файл пароля почты. Если вход задан, а пароля нет, `xtab doctor` предупреждает об этом.

## Частые ситуации

| Что видно | Что проверить |
|---|---|
| Страница не открывается | `docker compose ps`: все ли сервисы `healthy`; `docker compose logs caddy xtab`; сертификат и DNS домена |
| Узел не стартует, в журнале «schema version … is newer than this binary» | Запущена версия старше схемы базы, и обновление изменило базу несовместимо с ней: вернитесь на новую версию или восстановите копию перед обновлением (`sudo ./install.sh --restore`) |
| Узел не стартует, в журнале «database schema differs from this binary» | База не от этой линии версий или изменён файл миграции: запустите версию, которая её обновляла, или восстановите копию |
| После отката таблица или представление не открываются, в журнале узла «stored settings do not read» | Их настройки сохранила более новая версия, и прежняя их не читает. Она ничего в них не меняет; остальные таблицы работают, автоматизации этой таблицы не срабатывают. Установите снова новую версию её комплектом или восстановите копию, снятую перед обновлением |
| «Повторите позже» при загрузке файлов, в проверке состояния `degraded` | Хранилище недоступно: `xtab doctor`, сеть и ключи S3 |
| Письма не приходят | Подключён ли `docker-compose.egress.yml`, настройки почты, `xtab doctor --mail-probe` на узле фоновых задач; письма ждут в очереди и уйдут, когда сервер станет доступен |
| Импорт отклонён «слишком много строк, колонок или ячеек» | Файл больше пределов импорта: 200 000 строк, 500 колонок, 5 млн ячеек между первой и последней заполненной ячейкой листа |
| Установка «только чтение» | `docker compose run --rm migrate license show`: срок лицензии или причина |
| Пользователь потерял второй фактор | Администратор организации сбрасывает его в панели; если потеряли все администраторы — `user reset-2fa` консолью |
| `XtabBackupWalLag` | Доступно ли хранилище копий; `xtab backup status` на узле фоновых задач |

Для обращения в поддержку приложите вывод `xtab doctor --format json` и журналы узлов за время проблемы. Пароли и ключи в них не попадают.
