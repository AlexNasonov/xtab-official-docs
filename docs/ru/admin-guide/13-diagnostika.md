## `xtab doctor`

Первое, что стоит запустить при любой проблеме:

```bash
docker compose run --rm migrate doctor                 # конфигурация, база, роли, хранилище, почта, лицензия
docker compose exec xtab-worker xtab doctor            # плюс ключ и свежесть резервных копий
docker compose run --rm migrate doctor --storage-probe # хранилище с составной загрузкой
```

Она проверяет:

- конфигурацию;
- версию PostgreSQL и расширения;
- роли и права базы, бюджет соединений;
- хранилище и почту;
- часы и лицензию;
- давность резервной копии и проверки восстановления.

Каждая строка — «в порядке», предупреждение или ошибка с подсказкой. Вывод в JSON — `--format json`.

## Частые ситуации

| Что видно | Что проверить |
|---|---|
| Страница не открывается | `docker compose ps`: все ли сервисы `healthy`; `docker compose logs caddy xtab`; сертификат и DNS домена |
| Узел не стартует, в журнале «schema is newer» | Запущена версия старше схемы базы: вернитесь на новую или восстановите копию |
| «Повторите позже» при загрузке файлов, в проверке состояния `degraded` | Хранилище недоступно: `xtab doctor`, сеть и ключи S3 |
| Письма не приходят | Подключён ли `docker-compose.egress.yml`, настройки почты, `xtab doctor` на узле фоновых задач; письма ждут в очереди и уйдут, когда сервер станет доступен |
| Импорт отклонён «слишком много строк, колонок или ячеек» | Файл больше пределов импорта: 200 000 строк, 500 колонок, 5 млн ячеек между первой и последней заполненной ячейкой листа |
| Установка «только чтение» | `docker compose run --rm migrate license show`: срок лицензии или причина |
| Пользователь потерял второй фактор | Администратор организации сбрасывает его в панели; если потеряли все администраторы — `user reset-2fa` консолью |
| `XtabBackupWalLag` | Доступно ли хранилище копий; `xtab backup status` на узле фоновых задач |

Для обращения в поддержку приложите вывод `xtab doctor --format json` и журналы узлов за время проблемы. Пароли и ключи в них не попадают.
