1. Проверьте подпись архива, если у вас есть cosign: команда указана в заголовке `install.sh`.
2. Распакуйте архив и запустите установщик:

   ```bash
   tar -xzf xtab-VERSION-linux-ARCH.tar.gz
   cd xtab-VERSION-linux-ARCH
   sudo ./install.sh
   ```

3. Ответьте на вопросы:

   | Вопрос | Варианты |
   |---|---|
   | Домен | Имя DNS установки |
   | Сертификат | Let's Encrypt (нужен интернет и порт 80) / свой центр сертификации Caddy (закрытый контур) / свои файлы сертификата и ключа |
   | Хранилище файлов | Встроенное / ваше S3 |
   | Почта | Без почты / ваш сервер SMTP |
   | Лимиты памяти контейнеров и кэш базы данных | Предложенные по объёму памяти / свои |
   | Вход через Active Directory / LDAP | Да — ставится Keycloak / нет |
   | Первая организация | Название и e-mail администратора |

   Ключи S3, сертификат и пароль почты указываются путями к файлам на этой машине: сами секреты не вводятся и не показываются.

4. Установщик запустит сервисы, проверит работу через HTTPS и в конце один раз покажет ссылку администратора первой организации. Ссылка действует 24 часа. Новую выдаёт команда в каталоге установки:

   ```bash
   docker compose run --rm migrate user access-link --email admin@example.ru
   ```

Язык установщика — из `LANG` или ключом `--lang ru|en`, каталог — ключом `--dir`.

## Установка файлом ответов

Для нескольких одинаковых стендов те же ответы задаются файлом. Все ключи с пояснениями и значениями по умолчанию — в `install.example.toml` комплекта: скопируйте его в `install.toml` и поправьте.

```toml
domain = "xtab.example.ru"

[tls]
mode = "internal"        # internal — свой центр сертификации, acme — Let's Encrypt, files — свои файлы

[storage]
kind = "builtin"         # builtin — встроенное хранилище, s3 — ваше S3

[organization]
name = "ООО Ромашка"
admin = "admin@example.ru"
```

```bash
sudo ./install.sh --answers install.toml --yes
```

Неизвестный ключ в файле — ошибка: опечатка не останется незамеченной.

## Своё хранилище S3

Хранилище должно поддерживать адресацию path-style и подпись SigV4. Ключу Xtab нужны чтение, запись и удаление объектов и составная загрузка (multipart) в его bucket. Установщик проверит хранилище до записи настроек: запишет, прочитает и удалит пробный объект. Версионирование bucket не нужно; для брошенных частей составных загрузок заведите правило очистки. Если сертификат хранилища выдан вашим центром сертификации, укажите его файл (`ca_file`). Для резервных копий заранее создайте в том же S3 второй bucket (установщик спросит его имя, по умолчанию `xtab-backups`) с теми же правами ключа или укажите S3 копий на другой машине: установщик проверит и его, при установке и при каждом обновлении, и не продолжит, пока копиям некуда уходить.

Хранилище по `http://` вне машины передаёт вложения открытым текстом — используйте HTTPS.

## После установки

- Каталог установки — обычный проект Docker Compose: `docker compose ps`, `docker compose logs <сервис>`.
- Секреты — в `secrets/`. Сохраните отдельно от сервера и от резервных копий:
  - `master_key` — без него восстановленная база не откроется;
  - `backup_key` — закрытый ключ резервных копий, без него копии не прочитать;
  - `audit_signing_key` — ключ подписи журнала аудита;
  - `audit_archive_key` — закрытый ключ архива журнала аудита.
- Свои правки — только в `docker-compose.override.yml` и `caddy/local/*.caddy`: обновление их не меняет.
- Повторный запуск установщика безопасен: секреты и данные сохраняются. Сменить ответы — `sudo ./install.sh --reconfigure`.
