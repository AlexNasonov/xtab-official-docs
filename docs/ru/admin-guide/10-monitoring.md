## Метрики и алерты

Узлы отдают метрики Prometheus на внутреннем порту 9090, наружу он не публикуется. В папке `monitoring/` комплекта лежат фрагмент настроек Prometheus, правила алертов и дашборд Grafana; сами Prometheus и Grafana в комплект не входят. Полный список метрик — в каталоге метрик.

Главные алерты:

| Алерт | Что значит |
|---|---|
| `XtabNodeDown` | Узел не отвечает |
| `XtabErrors`, `XtabSlowRequests`, `XtabOverloaded` | Ошибки, медленные ответы, сброс нагрузки |
| `XtabJobsDead`, `XtabJobsWaiting` | Фоновые задачи не проходят или копятся |
| `XtabBackupWalLag`, `XtabBackupFailed` | Журнал базы не уходит в копии, полная копия не снята |
| `XtabAuditChainBroken`, `XtabAuditSealFailures`, `XtabSiemFailures` | Целостность журнала аудита, его печать, выгрузка в SIEM |
| `XtabDependencyDown` | Узел работает без хранилища или почты |
| `XtabSecurityAlerts` | Новое оповещение безопасности |

## Проверка состояния

- **`https://<домен>/health/ready`** отвечает `200 ready`, когда узел готов: база доступна, миграции применены, узел не останавливается.
- **Подробная проверка** — внутренний порт `9090`, путь `/health/ready`. Она отвечает JSON с состоянием пулов соединений и служб вне узла (хранилище; на узле фоновых задач — почта).
- **Деградация.** Если хранилище или почта недоступны, узел остаётся «готов», но помечает `degraded`. В таком режиме записи читаются и правятся, загрузка и выдача файлов отвечают «повторите позже», письма ждут в очереди. Если недоступен провайдер входа, вход через него возвращает на страницу входа, а пароль и сессии работают.

## Журналы

Узлы пишут журналы в формате JSON в стандартный вывод контейнера: `docker compose logs xtab xtab-worker`. Пароли, токены и ключи в журналах не появляются. Уровень журналов меняется без перезапуска настройкой `log.level`.

Трассировка OpenTelemetry выключена по умолчанию. Если включить её разделом `[tracing]` конфигурации (адрес вашего коллектора), наружу уходят только метод, шаблон адреса, статус и номер запроса — без данных пользователей.
