## Как копируется установка

Установка копирует себя сама:

- каждый завершённый сегмент журнала базы — не реже раза в минуту;
- полная копия базы — каждую ночь;
- файлы баз — раз в час, если копии хранятся на отдельном S3.

Всё шифруется и подписывается: узлы шифруют копии открытой частью ключа `secrets/backup_key` и прочитать их не могут. Храните этот ключ отдельно от копий.

| Что | Сколько хранится |
|---|---|
| Ежедневные полные копии | 14 дней |
| Ежемесячные | 12 месяцев |
| Журнал базы | 7 дней |

Сроки меняются в настройках инстанса. По умолчанию копии лежат в bucket `xtab-backups` хранилища файлов этой же машины. Чтобы копии пережили потерю диска, укажите в ответах установщика (раздел `[backup]`) S3 на другой машине.

```bash
docker compose exec xtab-worker xtab backup now      # полная копия вне расписания
docker compose exec xtab-worker xtab backup status   # последние копии и отставание журнала
```

## Восстановление на момент времени

```bash
sudo ./restore.sh --to-time 2026-11-08T10:00:00Z
```

Без `--to-time` установка возвращается к последнему отправленному сегменту журнала. Сценарий:

1. останавливает узлы;
2. проверяет подписи и расшифровывает копию;
3. откладывает текущие данные базы в том `restore` (не откладывать — `--discard-current`);
4. проигрывает журнал до момента;
5. возвращает пропавшие файлы из их копий (если копии на отдельном S3);
6. запускает узлы и проверяет журнал аудита.

В конце сценарий печатает, сколько заняло восстановление. Изменения после выбранного момента теряются.

## Проверка восстановления

Проверяйте восстановление на отдельной машине хотя бы раз в квартал. Панель администратора инстанса и `xtab doctor` напоминают, если проверки не было 90 дней. Записать проверенное восстановление вручную:

```bash
docker compose exec xtab-worker xtab backup checked --seconds 1200
```
